Ferrante - The Program Dependence Graph and Its Use in Optimization
ACM TOPLAS 1987Strong		 Introduces the PDG, one graph that makes both data dependences and control dependences explicit for every operation, so a single walk over dependences supports optimizations and slicing. p1 abstract: data + control dependences in one graph, control dependences derived from the control flow graph; key words list slicing and data flow.
  • src/symbols/indexer.py:1232-1349per-statement records with parent_statement_id (enclosing if/match/for/while/loop) and previous_statement_id
  • src/graph/builder.py:687-700CONTROL_FLOW edge, relation="sequential"
  • src/graph/builder.py:702-715DEPENDENCE edge, relation="control" (parent statement → child)
  • src/graph/builder.py:744-771DATA_FLOW edge from last write of a target to a later read
  • src/backends/ryugraph/queries.py:301-343, 501-533statement_slice: statements + reads/writes/calls + control predecessors/successors
  • src/agents/toolkit.py:546-592statement_slice agent tool
 Builds a statement-level dependence graph per function with control and data edges, and exposes slicing over it as an agent tool. Same representation goal: control and data dependence as explicit edges, traversed for slicing. Differences: control dependence in the code is approximated by syntactic nesting (control_stack), not post-dominator analysis on a CFG; DATA_FLOW links the last write in line order, not CFG reaching definitions. Used for retrieval, not compiler optimization.
